# Прайс-срез: «все шардоне из этого прайса»

**Дата:** 2026-10-01
**Статус:** дизайн согласован, готов к плану реализации
**Ветка:** `feat/price-slice`

## Задача

Кидаю прайс поставщика в телеграм-бота «Чип и Дейл» с фразой вроде «все шардоне» — получаю
таблицу: производитель, название, регион, год, цена.

Три рабочих сценария, под которые это делается:

1. **Выбрать, что закупить** — вижу весь сорт у поставщика сразу, сравниваю цены и регионы.
2. **Ответить на запрос клиента/B2B** — «есть шардоне до 600?» → ответ с телефона за минуту.
3. **Разобрать прайс незнакомого поставщика** — понять, что у него вообще есть, до начала работы.

## Принятые решения

| Решение | Значение |
|---|---|
| Судьба файла | **Разовый разбор.** Ничего не пишется в `wine_items` и не создаёт `price_list` |
| Умность фильтра | **Умный + пометка уверенности.** Chablis/Meursault добираются и помечаются |
| Входная дверь | **Чип и Дейл** (`01_agents/bot`) |
| Формат ответа | **Список в чате (10 позиций) + CSV-вложение с полной таблицей** |
| Язык запроса | **Свободный фильтр** (сорт, цвет, страна, регион, цена, год), сортировка по цене |
| Доуточнение | **Вторым сообщением**, без повторного парсинга файла |
| Архитектура | **Подход A:** эндпоинт в `mission-control` + тонкая команда в боте |

### Вне скоупа (сознательно)

- Пометка «это у нас уже есть» (матчинг с Loyverse-стоком) — отдельный матчинг, отдельная задача.
- Заливка разобранного прайса в базу. Если прайс нужен в базе — существующий `/m/price/upload`.
- Страница в портале под этот сценарий.
- Сборка винной карты партнёру из среза.
- Генерация `.xlsx` (CSV достаточно и не тянет библиотеку в бота).

## Почему подход A

Парсинг прайсов в проекте уже построен и отлажен: `extractFromFile()` в
[`lib/price/extract.ts:37`](../../../02_services/mission-control/lib/price/extract.ts#L37) —
19 парсеров под конкретных поставщиков, а для незнакомых файлов каскад
pdftoppm → текст → Claude Vision. Функция **чистая**: принимает буфер, возвращает
`ExtractionResult`, в базу ничего не пишет. Ровно то, что нужно разовому разбору.

Отвергнутые альтернативы:

- **Всё в боте одним вызовом Claude** — игнорирует 19 парсеров, ломается по токенам на
  прайсе в 300+ позиций, цены «на глаз» модели. Для закупки неприемлемо.
- **Вынести `extract` в `@ww/shared`** — тянет poppler/`pdftoppm` и системные зависимости в
  контейнер бота; shared-пакет к тому же до сих пор ждёт перенастройки Railway.

## Архитектура

```
Телеграм (Чип и Дейл)                      mission-control
─────────────────────                      ──────────────────
«/price все шардоне» + файл
   │ downloadTelegramFile()
   ├─ POST /api/public/price/slice ──────→ extractFromFile()  ← 19 парсеров / Claude
   │   multipart{file, query}              ↓
   │                                       sliceItems():
   │                                         шаг 0: фраза → SliceQuery   (LLM)
   │                                         шаг 1: фильтр по полям      (детерминированно)
   │                                         шаг 2: добор по апелласьону (LLM, по остатку)
   │                                         шаг 3: раскол producer/cuvée (LLM, по срезу)
   ←── {supplier, rows[], items[], …} ─────┘
   │
   ├─ formatSliceMessage() → список в чате
   ├─ buildSliceCsv()      → chardonnay_janhom_2026-10-01.csv
   └─ priceSliceCache.set(chatId, items)   TTL 30 мин
         │
         └─ reply на сообщение среза → POST /api/public/price/slice/refine
                                        (items из кэша, без парсинга файла)
```

Двухшаговый фильтр — это и есть «пометка уверенности»: шаг 1 нашёл слово в самом прайсе,
шаг 2 — вывод бота по апелласьону. В выдаче они различимы.

## Компонент 1: `lib/price/slice.ts` (mission-control)

Чистая логика среза. Не знает ни про HTTP, ни про телеграм, ни про Supabase.

```ts
export type SliceQuery = {
  grapes: string[]          // нормализованные латиницей: ['chardonnay']
  colors: WineColor[]       // 'red' | 'white' | 'rose' | 'orange' | 'sparkling'
  countries: string[]       // lowercase, как пишут в прайсах: ['france', 'italy']
  regions: string[]
  categories: Category[]    // 'wine' | 'spirits' | 'beer' | 'other'
  priceMin: number | null
  priceMax: number | null
  yearMin: number | null
  yearMax: number | null
  sort: 'price_asc' | 'price_desc' | 'name'
  text: string | null       // остаточные слова — ищутся в name/description
}

export type SliceRow = {
  producer: string | null
  name: string              // без производителя, если раскол удался
  region: string | null
  country: string | null
  year: number | null
  price: number | null
  volume: string | null
  match: 'explicit' | 'inferred'
  note: string | null       // 'по апелласьону', 'бленд', 'Chablis'
}

export type SliceResult = {
  query: SliceQuery
  rows: SliceRow[]
  totalItems: number        // сколько всего позиций в прайсе
  matched: number           // сколько прошло фильтр
}
```

Функции:

- **`parseSliceQuery(text: string): Promise<SliceQuery>`** — один дешёвый вызов Claude Haiku:
  фраза → JSON. Ответ прогоняется через `coerceSliceQuery()`.
- **`coerceSliceQuery(raw: unknown): SliceQuery`** — чистая валидация: неизвестные цвета и
  категории отбрасываются, цены/годы приводятся к числам, `sort` по умолчанию `price_asc`,
  сорта нормализуются через `GRAPE_SYNONYMS`. Это точка, которую покрывают тесты.
- **`applySliceFilter(items: ExtractedItem[], q: SliceQuery): { explicit: Hit[]; candidates: ExtractedItem[] }`**
  — детерминированный шаг 1. `explicit` — прошли всё. `candidates` — прошли все ограничения,
  кроме сорта, и при этом `category === 'wine'` (материал для шага 2).
- **`inferByAppellation(candidates, q): Promise<Hit[]>`** — шаг 2. Не запускается, если
  `q.grapes` пуст. Батчами по 100 отправляет Claude компактный список `{i, name, region,
  country}` и просит вернуть индексы тех, что сделаны из этого сорта, с коротким основанием.
  Промпт запрещает добавлять что-либо кроме классификации. Результат → `match: 'inferred'`.
- **`splitProducer(rows: SliceRow[]): Promise<SliceRow[]>`** — шаг 3. `ExtractedItem` не
  содержит производителя: в прайсах он слит с названием («Louis Jadot Bourgogne Chardonnay»),
  детерминированно не делится. Один вызов Claude **только по отобранным строкам** (их десятки,
  не сотни). Не удалось — `producer: null`, `name` остаётся целиком.
- **`sliceItems(items, queryText): Promise<SliceResult>`** — оркестрация шагов 0–3 + сортировка.

### `GRAPE_SYNONYMS`

Небольшой расширяемый словарь в том же файле: `chardonnay: ['chardonnay', 'chard']`,
`pinot gris: ['pinot gris', 'pinot grigio', 'grauburgunder']`, и т.п. Начинаем с сортов,
которые реально встречаются на полке; расширяется по одной строке.

**Бленды.** «Chardonnay-Semillon» попадает в срез по шардоне как `match: 'explicit'`
с `note: 'бленд'` — слово в прайсе есть, решение о покупке за человеком.

## Компонент 2: `POST /api/public/price/slice`

Живёт в `app/api/public/price/slice/route.ts` — под `/api/public/`, чтобы middleware не
требовал куки-сессию (у бота её нет). Авторизация — bearer-секрет, ровно как в
[`payables-alerts`](../../../02_services/mission-control/app/api/public/payables-alerts/route.ts):
`Authorization: Bearer <PRICE_SLICE_SECRET>` или `x-api-key`. Нет env — `503 not configured`.

- **Вход:** `multipart/form-data` — `file` (PDF/XLS/XLSX/JPG/PNG/WEBP по `ACCEPTED_TYPES`),
  `query` (строка).
- **Выход:**
  ```json
  { "supplier_name": "...", "price_list_date": "2026-09-12", "currency": "THB",
    "total_items": 214, "matched": 14, "query": { }, "rows": [ ], "items": [ ] }
  ```
  `items` — все извлечённые позиции, бот кладёт их в кэш для доуточнения.
- **Коды:** `400` неподдерживаемый тип / пустой `query`, `401` секрет не совпал,
  `422` в файле не нашлось ни одной позиции, `503` не сконфигурирован, `500` остальное.
- **Лимиты:** файл ≤ 20 МБ (это и так предел Telegram `getFile`). `export const maxDuration = 300`
  — большой PDF через Vision идёт минутами. `export const dynamic = 'force-dynamic'`.

## Компонент 3: `POST /api/public/price/slice/refine`

Тот же файл-соседа `.../slice/refine/route.ts`, та же авторизация. Принимает JSON
`{ items, query }`, зовёт `sliceItems` без извлечения, возвращает тот же `SliceResult`
(без `items` — они у бота уже есть). Прайс в 500 позиций ≈ 150 КБ JSON, это нормально.

## Компонент 4: бот — `01_agents/bot/src/price-slice.ts`

Новый модуль; `index.ts` только подключает хендлеры.

**Вход в режим — явный,** потому что `message:document` в боте уже занят PO-сканами
([`index.ts:572`](../../../01_agents/bot/src/index.ts#L572)) и PDF прайса иначе уйдёт в
распознавание PO:

1. **`/price`** — с текстом запроса или без. Ставит `pendingPriceSlice.set(chatId, {query})`.
   Следующий документ/фото от этого чата идёт в срез, а не в PO. Проверка этого состояния
   стоит **перед** существующей логикой в обоих хендлерах: `message:document` (там PO-сканы)
   и `message:photo` (там расходы).

   Команда латиницей не из вредности: Telegram разбирает как `bot_command` только
   `[a-zA-Z0-9_]`, `/прайс` просто не станет командой. Поэтому вторым входом —
   **текст или подпись к файлу, начинающийся со слова «прайс»** («прайс: все шардоне»).
   Это префиксная проверка конкретного первого слова, а не перехват всех сообщений.
2. Бонусом: когда PO-классификатор отвечает «не распознал как PO», к сообщению подкладывается
   инлайн-кнопка **«Это прайс-лист →»**. Файл уже скачан — по нажатии бот спрашивает
   «Что нужно из прайса?» и дальше обычный поток.

**Доуточнение** — только однозначными путями, чтобы не перехватывать каждое текстовое
сообщение (там живут расходы):

- **reply** на сообщение со срезом (`ctx.message.reply_to_message.message_id` совпадает с
  сохранённым id) → `refine`;
- `/price <новый запрос>` (или «прайс: …») без файла при тёплом кэше → `refine`.

Кэш: `Map<chatId, { items, supplier, messageId, ts }>`, TTL 30 минут, как уже сделано для
`pendingPhotos`/`pendingWeight`. Редеплой кэш теряет — файл присылается заново, это приемлемо.

**Вывод в чате** (`parse_mode: "HTML"`, как в остальном боте; все значения экранируются):

```
Janhom · прайс от 12.09.2026
Шардоне: 14 позиций, ฿380–2,450

1. Louis Jadot · Bourgogne Chardonnay
   Бургундия, FR · 2022 · ฿1,180
2. Domaine Laroche · Chablis St Martin
   Шабли, FR · 2021 · ฿1,890  ◦ по апелласьону
…
…и ещё 4 — в файле
```

Первые 10 в порядке сортировки запроса. Пустой срез — «По запросу ничего не нашёл.
В прайсе 214 позиций» + подсказка переформулировать.

**CSV** (`buildSliceCsv`): колонки `производитель,название,регион,год,цена,объём,пометка`.
BOM `﻿` и CRLF — чтобы тайский Excel открывал без танцев. Цена числом без разделителей
разрядов. Имя файла: `<слаг-запроса>_<поставщик>_<YYYY-MM-DD>.csv`.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Портал недоступен / таймаут | «Портал не ответил, попробуй ещё раз» + ошибка в лог через существующий `reportFailure` |
| В файле не нашлось позиций (`422`) | «Не смог прочитать это как прайс-лист. Если это PO — пришли без подписи» |
| Фраза не распарсилась в фильтр | Срез не делается: «Не понял запрос. Например: „все шардоне до 600“» |
| LLM-шаг 2 упал | Отдаём только `explicit`-строки + строка «добор по апелласьону не сработал» |
| LLM-шаг 3 упал | `producer: null`, названия целиком — срез всё равно полезен |
| Файл > 20 МБ | Телеграм сам не отдаст — ловим ошибку `getFile` и просим прислать поменьше |

Принцип: падение любого LLM-шага **деградирует** срез, но не отменяет его.

## Тестирование

**Чистые юниты (vitest, уже настроен в обоих пакетах):**

- `coerceSliceQuery` — мусор от модели, неизвестные цвета, цены строками, дефолт сортировки.
- `applySliceFilter` — синонимы (Pinot Grigio ↔ Pinot Gris), бленд «Chardonnay-Semillon»
  как `explicit` + `note`, границы цены и года, фильтр по цвету/стране, формирование
  `candidates` (только `category === 'wine'`).
- `buildSliceCsv` — запятые и кавычки в названиях, BOM, пустой срез.
- `formatSliceMessage` — отсечение на 10 позициях, HTML-экранирование, пометка `inferred`.

**Интеграционный тест** на существующих фикстурах `lib/price/__fixtures__/harvest-*.json`:
прогнать `sliceItems` по разобранному прайсу Harvest с замоканными LLM-шагами и проверить,
что детерминированный шаг 1 находит ожидаемые позиции.

LLM-шаги (`parseSliceQuery`, `inferByAppellation`, `splitProducer`) в тестах мокаются —
проверяется разбор и деградация ответа, а не сама модель.
