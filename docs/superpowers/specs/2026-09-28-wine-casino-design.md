# Wine Casino — дизайн

**Дата:** 2026-09-28
**Статус:** утверждён, готов к планированию

## Задача

Многопользовательская игра-дегустация «Винное казино» для мероприятий Wine & Whiskey.
Принцип подключения как в Kahoot: ведущий создаёт игру, гости заходят со своих
телефонов по QR/PIN. Механика — классическое винное казино: слепая дегустация,
ставки фишками на характеристики вина, выплаты по коэффициентам.

## Правила классического винного казино (исследование)

- 5–8 вин, один раунд = одно вино, наливается вслепую.
- Все игроки получают одинаковый стартовый банк фишек.
- Игровое поле вместо чисел рулетки содержит категории: стиль (сухое/сладкое),
  Старый/Новый Свет, страна, регион, сорт винограда, год урожая, крепость.
- Фишки можно дробить между вариантами.
- Коэффициенты растут со сложностью категории; год урожая — самый дорогой.
- Угадал → ставка умножается, ошибся → фишки уходят «казино».
- После вскрытия ведущий-сомелье рассказывает про вино — образовательная часть.
- Победитель по банку фишек (в классике часто финальный аукцион на призы).

Источники: rbc.ru/wine, dcwmagazine.com, winecasino.moscow, ait.wine, gourmetshop.ru.

## Архитектура

Next.js 15 + React 19 + Tailwind, как остальные сервисы репо. Деплой на Railway
по push в `main`. Хранилище — существующий Supabase проекта (`arbturzdpqvulsqwqpbd`),
новая схема `casino`.

| Маршрут | Кто | Аутентификация |
|---|---|---|
| `/` | Гость с телефона | PIN из 6 цифр + ник, без аккаунта |
| `/host` | Ведущий | host-токен в ссылке |

### Модель данных (схема `casino`)

**`game`**
- `id` uuid pk, `pin` text unique (6 цифр), `host_token` uuid
- `title`, `status` (`draft` | `lobby` | `running` | `finished`)
- `difficulty` (`easy` | `medium` | `hard` | `pro`)
- `starting_chips` int (default 100), `rescue_chips` int (default 10)
- `round_seconds` int (default 120)
- `categories` jsonb — список активных категорий с коэффициентами
- `created_at`

**`game_wine`** — приватная, анонимному ключу доступ запрещён
- `id`, `game_id`, `order_no`, `label` («Вино №3»)
- `sku` nullable (ссылка на инвентарь), `name`, `country`, `region`, `grape`,
  `vintage`, `style`, `abv`, `image_url`
- `answers` jsonb — правильные ответы по категориям
- `options` jsonb — варианты ответов по категориям (RU + EN)
- `hints` jsonb — `[{ at_seconds_remaining, text_ru, text_en }]`
- `status` (`pending` | `betting` | `locked` | `revealed`), `started_at`, `ends_at`

**`round_state`** — публичная проекция, единственное, что видит телефон.
Одна строка на игру (pk = `game_id`), перезаписывается при каждой смене раунда.
- `game_id`, `wine_id`, `label`, `status`, `ends_at`
- `options` jsonb (варианты — их показывать можно)
- `revealed_hints` jsonb (только уже выпавшие)
- `revealed_answers` jsonb nullable (заполняется только при вскрытии)

**`player`**
- `id`, `game_id`, `nickname`, `chips`, `lang`, `joined_at`

**`player_secret`** — приватная
- `player_id`, `token_hash`

**`bet`**
- `id`, `game_id`, `wine_id`, `player_id`, `category`, `option`, `amount`
- `is_correct` nullable, `payout` nullable
- unique (`player_id`, `wine_id`, `category`, `option`)

Правильные ответы физически недоступны клиенту: они живут в `game_wine`, закрытой
RLS, а расчёт выплат выполняется на сервере.

## Поток игры

1. Админ создаёт игру: сложность, стартовый банк, длительность раунда, набор
   категорий с коэффициентами.
2. Добавляет 5–8 вин. Поиск по инвентарю подставляет страну, сорт, год; недостающие
   поля дозаполняются вручную. Система генерирует варианты ответов и подсказки,
   админ может править.
3. ТВ открывает `/screen/<pin>`, ведущий — `/host`. Статус игры → `lobby`.
4. Гости сканируют QR, вводят ник, видят стартовый банк.
5. Ведущий наливает вино вслепую и жмёт «Начать раунд». Статус → `betting`,
   `ends_at` = now + `round_seconds`.
6. По расписанию сложности сервер дописывает подсказки в `revealed_hints`.
7. Таймер истёк или ведущий закрыл раньше → `locked`, новые ставки отклоняются.
8. Ведущий жмёт «Вскрыть» → сервер считает выплаты, обновляет `player.chips`,
   заполняет `revealed_answers`. Статус → `revealed`.
9. Ведущий рассказывает про вино, жмёт «Следующее вино».
10. После последнего вина — `finished`, пьедестал на ТВ.

## Ставки и выплаты

- Игрок распределяет фишки из банка по вариантам; можно ставить в нескольких
  категориях и на несколько вариантов внутри одной категории (хедж).
- Сумма ставок не может превышать банк. Пас разрешён.
- Угадал → возвращается `ставка × коэффициент категории`. Ошибся → ставка сгорает.
- Категории ставок по умолчанию и их коэффициенты: стиль ×1.5, Старый/Новый Свет ×2,
  страна ×4, сорт ×6, регион ×8, год ×10. Набор и коэффициенты настраиваются на
  уровне игры. Крепость (`abv`) хранится в карточке вина и показывается при вскрытии,
  но категорией для ставок по умолчанию не является.
- **Спасательные фишки:** если после расчёта раунда банк игрока равен нулю, ему
  начисляется `rescue_chips` (10). Отклонение от классики: без него гость выбывает
  на третьем вине из восьми и остаётся зрителем до конца вечера.

## Подсказки

Генерируются шаблонами из полей вина, без AI:

- «Это Старый Свет» / «Это Новый Свет»
- «Год между 2018 и 2020» (диапазон ±2 от истинного)
- «Страна начинается на букву И»
- «Сорт красный, на букву S»
- «Регион: Италия, на букву Т»

Расписание по сложности (время — сколько секунд осталось до конца раунда; при
нестандартной длительности раунда пересчитывается пропорционально от 120 сек):

| Уровень | Подсказки |
|---|---|
| `easy` | 3 шт: на 90 / 60 / 30 |
| `medium` | 2 шт: на 60 / 25 |
| `hard` | 1 шт: на 25 |
| `pro` | нет |

Подсказки не влияют на коэффициенты. Админ может отредактировать текст любой
подсказки или удалить её.

## Реалтайм

Supabase Realtime, подписка на `round_state` и `player` по `game_id`. Таймер тикает
локально и синхронизируется по `ends_at` из базы — тики по сети не гоняются.
При потере сокета — фолбэк на опрос раз в 3 секунды.

## Языки

RU + EN, переключатель у каждого игрока. Строки интерфейса — простой словарь в коде,
без i18n-библиотеки. Названия стран и сортов — словарь переводов в коде. Подсказки и
варианты ответов хранятся в двух языках.

## Тестирование

Vitest, как в mission-control.

- Юнит: расчёт выплат (`settleRound`), генератор вариантов ответов, генератор
  подсказок и расписания, применение спасательных фишек.
- Правила ставок: нельзя превысить банк, нельзя ставить после `locked`, нельзя
  ставить в чужую игру, нельзя ставить в категорию, отключённую в игре.
- Ручной прогон: три браузера в мобильном режиме + экран ТВ.
