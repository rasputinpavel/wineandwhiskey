# Payments — единое место правды (consolidate PO surfaces)

**Дата:** 2026-06-29
**Статус:** draft (на ревью пользователя)
**Сервис:** `02_services/mission-control`

## Проблема

PO-данные показываются на трёх экранах, что создаёт ощущение дублирования и
путает, где «правда» по оплатам:

1. **Глобальная вкладка** `/m/suppliers/purchase-orders` — список всех PO за
   месяц с редактируемыми Paid / Docs / Cashflow-override (экран-источник
   жалобы).
2. **Карточка поставщика** `/m/suppliers/[id]` — PO конкретного поставщика, тоже
   с редактируемыми Paid / Docs / Cashflow-override и прогнозной датой платежа.
3. **Payment Calendar** `/m/payment-calendar` — двусторонний таймлайн OUT
   (кредиторка: PO + отсрочка) / IN (дебиторка: B2B-инвойсы) с бегущим NET;
   Paid / Docs редактируются здесь же.

**Ключевой факт:** дублирования *данных* нет. Все три экрана читают одну
таблицу `public.purchase_orders` и одну колонку `paid_at`, используют один и тот
же компонент `PaidAtCell`. Отметка оплаты в любом месте пишет в одно поле.
Расхождение, которое заметил пользователь («в календаре оплаты есть, в PO
пусто»), объясняется разным охватом по умолчанию: глобальная вкладка фильтрует
по `order_date` выбранного месяца, а календарь в режиме Open показывает всё
неоплаченное по всем месяцам.

## Цель

Одно место правды для **отметки оплат** = Payment Calendar. PO «отражаются»
внутри поставщика (карточка), но не редактируются там по части оплаты. Лишний
глобальный экран убираем.

## Решение

### 1. Payment Calendar — без изменений
Остаётся единственным местом, где ставится `paid_at` (и `docs_url`). Уже умеет
OUT/IN + NET. Не трогаем логику, только подтверждаем её роль.

### 2. Карточка поставщика `/m/suppliers/[id]` — отражение логики календаря
Цель: карточка показывает те же даты/статусы, что календарь, но **read-only по
оплате**.

- **Paid → read-only.** Вместо инлайн-редактора `PaidAtCell` рендерить
  отображение статуса:
  - оплачено → дата оплаты + зелёный бейдж/подсветка строки;
  - не оплачено → срок платежа `due = computeDueDate(order_date, terms)` и метка
    «просрочено N дн / сегодня / через N дн», подсветка строки (wine-red /
    amber), как в календаре и старом списке;
  - consignment / force-exclude → без срока, нейтрально.
- **Docs → read-only.** Показывать ссылку на Drive, если `docs_url` задан;
  редактирование — в календаре. Если ссылки нет — прочерк.
- **Cashflow-override → остаётся редактируемым** (`CashflowOverrideCell`).
  Обоснование: это классификация PO (auto / force-include / force-exclude), а не
  отметка оплаты; календарь её не редактирует (а лишь прячет consignment/
  exclude), а глобальная вкладка-хост удаляется — значит карточке поставщика
  становится единственным домом для override. **Решение для проверки
  пользователем:** ок ли, что override правится только тут.
- KPI карточки (Все PO / В cashflow / Оплачено / Не оплачено) — оставить.

### 3. Удалить глобальную вкладку «Purchase Orders»
- Удалить страницу `app/(portal)/m/suppliers/purchase-orders/page.tsx` (и пустой
  каталог).
- В `components/modules/suppliers/SuppliersNav.tsx` убрать таб
  `{ href: '/m/suppliers/purchase-orders', label: 'Purchase Orders' }` и
  связанную логику `SUB_ROUTES` (остаётся только «List» + drill-down `[id]`).
- Входящих ссылок на маршрут из других мест нет (проверено grep'ом: только
  сам файл-страница и таб в `SuppliersNav`).

## Что теряется и куда переехало

| Возможность глобальной вкладки | Куда переехало |
|---|---|
| Месячные cashflow-итоги (В / Не в cashflow) | Payment Calendar (месячный OUT) + KPI карточки поставщика |
| Отметка Paid по всем PO за месяц | Payment Calendar |
| Редактирование Docs | Payment Calendar |
| Редактирование Cashflow-override | Карточка поставщика |
| Фильтр draft/closed по всем PO | Карточка поставщика (фильтры уже есть) |

## Вне рамок (не трогаем)

- Таблицу `purchase_orders`, схему, скрейпер `scrape_purchase_orders.ts`.
- Расчёты Pulse / Rolling / месячный P&L.
- Дебиторку (IN-сторону календаря, FlowAccount-инвойсы).
- `inventory.supplier`, регистрацию поставщиков.

## Затрагиваемые файлы

- `app/(portal)/m/suppliers/[id]/page.tsx` — Paid/Docs read-only, выравнивание
  due-date/подсветки под календарь.
- `components/modules/suppliers/SuppliersNav.tsx` — убрать таб.
- `app/(portal)/m/suppliers/purchase-orders/page.tsx` — удалить.
- (возможно) общий хелпер подсветки/статуса, чтобы карточка и календарь считали
  одинаково — переиспользовать `computeDueDate` / `daysBetween` из `lib/kpi`.
