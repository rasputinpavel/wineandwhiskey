# Алан — рекомендации похожих вин («Похожие у нас»)

**Дата:** 2026-07-11
**Статус:** дизайн одобрен, готов к плану реализации
**Сервис:** `01_agents/alan` (+ новые публичные эндпоинты на `02_services/mission-control`)

## Проблема

Алан разбирает вино (фото/текст/голос) и выдаёт честный вердикт. Пользователь
хочет, чтобы после разбора Алан мог **рекомендовать похожие вина** — сначала из
того, что есть у нас в наличии, затем из того, что можно привезти у поставщиков,
и в конце — мировые ориентиры.

У Алана уже есть фича «глобальные аналоги» (`findAnalogues` / `analoguesSystemPrompt`
/ `AnaloguesResult`) — 3–5 вин со всего мира по стилю/уровню/цене, не привязанных к
стоку. Она покрывает только третий тир. Новую фичу строим как надстройку, тир «мир»
переиспользует существующий механизм.

## Решения (согласовано с пользователем)

1. **Три тира источников** (тройной проход): наличие Loyverse → каталог поставщиков → мир.
2. **Смысл «похожего» — «оба + пометка»:** показываем и равноценные, и «выгоднее»,
   помечая каждую рекомендацию ярлыком **ровня / дешевле и почти так же / апгрейд**.
3. **Триггер — по кнопке/запросу** (не авто): inline-кнопка «Похожие у нас» под вердиктом.
4. **Движок похожести — подход A (гибрид):** префильтр по атрибутам + LLM-реранк.
   Эмбеддинги (pgvector) — осознанно отложены, можно добавить позже за тем же seam.

## Контекст кодовой базы

- **Сток Loyverse** и **каталог поставщиков** (`wine_items`) живут в **mission-control**
  (туда переехал бывший price-service; там же Loyverse-синк и Vivino-обогащение).
  `wine_items` структурирован: `supplier_name, name, country, region, grape_variety,
  price, year, volume, description` + Vivino-поля.
- У Алана **отдельный Supabase-проект** (`arbturzdpqvulsqwqpbd`) — там только его кэш
  `alan_wine_cache`. Поэтому к стоку и каталогу Алан ходит **через публичный read-API
  mission-control**, а не в чужую БД напрямую (схема каталога живёт под миграциями
  mission-control и меняется).
- Уже есть образец публичного эндпоинта с секретом: `/api/public/payables-alerts`
  (`PAYABLES_ALERT_SECRET`), `/api/public/vivino/lookup` (`STOREFRONT_API_KEY`).
- В Алане есть seam `src/sources/` (реализации `WineDataSource`) и утилиты
  `priceLocal.ts` (THB↔USD, курс и тайский импортный множитель), `session.ts`
  (контекст последнего разбора, TTL 1 час).

## UX и поток

После обычного вердикта Алан показывает inline-кнопку **«Похожие у нас»**. По нажатию —
три блока, каждый **пропускается, если пусто**:

```
🍷 В наличии у нас
• Baron Philippe Cab Sauv — ฿890 · дешевле и почти так же
  Тот же плотный чилийский каб, на класс проще, но за полцены.

📦 Можем привезти (поставщики)
• Errazuriz Max Reserva — ~฿1 200 (IWS) · ровня
• Santa Rita Medalla Real — ~฿1 050 (Enoteka) · дешевле и почти так же

🌍 В мире есть (ориентир)
• Penfolds Bin 28 — ~$25 · апгрейд
```

- **Порядок тиров:** наличие → поставщики → мир (что можно купить прямо сейчас — выше).
- **До 3 позиций на тир.** Ярлык у каждой позиции.
- **Опорное вино берём из сессии** (`session.ts`) — повторный ресёрч не нужен.

## Движок похожести (подход A)

### Шаг 1. MatchProfile
Из готового `Verdict` собираем профиль **без новых LLM-вызовов**:
`{ type, grape, country, region, priceTier, qualityScore (0–100), marketUsd }`.
Это якорь для отбора и реранка. Чистая функция → юнит-тест.

### Шаг 2. Отбор кандидатов (стратегия под размер пула)
- **Loyverse (маленький, сотни позиций):** тянем весь винный сток в наличии
  (`/api/public/stock-candidates`) → отдаём список **целиком** в LLM (влезает в контекст).
- **Каталог поставщиков (тысячи строк):** SQL-префильтр на стороне mission-control
  (`/api/public/catalog-candidates`) — тот же `type` + совпадение по сорту/стране +
  ценовой коридор → шортлист ~30–50 → в LLM.
- **Мир:** переиспользуем существующий `findAnalogues` (web-поиск).

### Шаг 3. Реранк + ярлык (гибрид «код + LLM»)
- **Цену и направление считает код** детерминированно: есть цена якоря и цена
  кандидата, нормализуем через `priceLocal.ts`. Дешевле/ровня/дороже — арифметика,
  не галлюцинация. (Честность про цены — принцип Алана.)
- **Близость стиля и «почти так же» по качеству судит LLM** на реранке. У кандидатов
  из каталога есть Vivino-рейтинг для опоры; у стока часто нет — тогда LLM опирается
  на сорт/регион/цену.
- **Итоговый ярлык — комбинация:**
  - `дешевле + стиль близок + качество сравнимо` → «дешевле и почти так же»
  - `цена и качество рядом` → «ровня»
  - `дороже + заметно качественнее` → «апгрейд»

## Новые публичные эндпоинты (mission-control)

Оба — read-only, авторизация общим секретом в заголовке (новый env `RECO_API_SECRET`,
задаётся в mission-control и в Алане), по образцу payables-alerts.

**`GET /api/public/stock-candidates`**
Винный сток в наличии из Loyverse-инвентаря (on-hand > 0). Поля: name, price THB,
category, on-hand; если позиция слинкована с каталогом (`supplier_sku` /
`sku_wine_match_report`) — обогащённая сортом/страной. Возвращает весь винный сток
(сотни строк). Только вино (spirits/сигары отсекаются по категории).

**`GET /api/public/catalog-candidates?type=&grape=&country=&priceMinUsd=&priceMaxUsd=`**
Префильтр по `wine_items`: тот же тип + совпадение по сорту/стране + ценовой коридор,
лимит ~50, только вино. Поля: name, supplier_name, price, country, region,
grape_variety, year, Vivino-поля.

**Проверить на этапе плана (verifiable):** совпадает ли Supabase-проект Алана с
mission-control. Эндпоинты предпочтительны в любом случае (изоляция схемы), но факт
влияет на то, как mission-control достаёт Loyverse-инвентарь.

## Структура кода в Алане

Новый модуль `01_agents/alan/src/recommend/`, ложится на seam `src/sources/`:

| Файл | Ответственность |
|------|-----------------|
| `profile.ts` | `Verdict → MatchProfile` (чистая функция, юнит-тест) |
| `sources/stock.ts` | `StockSource` — дёргает `/api/public/stock-candidates` |
| `sources/catalog.ts` | `SupplierCatalogSource` — дёргает `/api/public/catalog-candidates` с префильтром |
| `sources/world.ts` | тонкая обёртка над существующим `findAnalogues` |
| `rank.ts` | LLM-реранк + детерминированный ярлык (код считает цену, LLM судит стиль) |
| `format.ts` (доп. к текущему) | сборка трёх блоков для Telegram |
| `recommend.ts` | оркестратор: профиль → 3 тира параллельно → сборка |

Кнопка и обработка callback — в `index.ts` (там уже telegram-хэндлеры и inline-кнопки).

## Обработка ошибок (best-effort, не роняем разбор)

- Тиры **независимы и идут параллельно**; упавший/пустой тир пропускается с тихой
  пометкой, а не ломает ответ.
- Если mission-control недоступен — тиры «наличие» и «поставщики» выпадают, **мир
  остаётся как fallback** (web-поиск ни от чего не зависит).
- Если пусто во всех трёх — честное «Похожего не нашёл» в голосе Алана, без выдумок.
- Бюджеты/таймауты — как в существующем ресёрче (лимит web-поиска у мира уже зашит).

## Что НЕ входит в v1 (YAGNI)

- **Кэш рекомендаций** — нет. Сток и прайсы волатильны, триггер ручной, латентность
  приемлема. Можно добавить позже (короткий TTL).
- **Эмбеддинги / pgvector** — отложено. При необходимости встаёт за тот же seam
  источников, без переписывания пайплайна.
- **Авто-триггер** после каждого разбора — нет (по решению пользователя, только кнопка).

## Тестирование

- `profile.ts` и код-часть ярлыка (расчёт направления цены) — детерминированы,
  покрываем юнит-тестами (`vitest`, как текущий suite).
- `StockSource` / `SupplierCatalogSource` — тесты с замоканным `fetch`.
- LLM-реранк — не юнит-тестируем на точность, но проверяем контракт схемы
  (structured output) на фикстурах.

## Валюты

Сток и прайсы поставщиков — в THB (Loyverse / тайские прайс-листы). Мир — в USD.
`priceLocal.ts` уже конвертирует THB↔USD; нормализуем всё к USD для сравнения цены,
отображаем в исходной валюте тира (฿ для наличия/поставщиков, $ для мира).
